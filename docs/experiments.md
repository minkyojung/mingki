# 실험 기록 (평가셋 측정)

같은 평가셋으로 개선 전 → 후를 비교한다. 검증 결과서 · README의 숫자는 이 문서와 같아야 한다.
재채점은 LLM 없이 정답지만 읽으므로, 저장된 결과 파일에서 언제든 같은 숫자를 다시 얻을 수 있다.

**EXP-01 분석.** 설명 확인 신설은 4.7 → 10.7로 올랐다. 코드가 P005(나이 상한 34) · P012(판매 종료)를 유지로 확정했고, 프롬프트가 바뀐 뒤 P006 · P007 · P008이 변경 필요로 나왔다. 남은 것은 P009(개인사업자, 3회 모두 틀림: 적용 대상으로 단정하거나 반대로 제외)와 P006 1회("고령자 계약 금지 자료가 없다"며 보류).
고령자 기준은 10.0 → 8.0으로 **떨어졌다**. 세 조항을 한 번에 분석하니 모델이 13번 원칙을 옆 요건에 섞어서, "고령자 기준 65세 → 60세" 요건에도 "설명 확인 의무를 반영해야 한다"고 답했다 (P001 · P003 · P004 · P010 · P011이 추가 확인). 원인은 프롬프트의 요건 분리 부족이다. 다음 단계는 "요건은 하나씩 따로 판단한다"는 원칙을 더하는 것(EXP-02).

**EXP-02 분석.** 설명 확인 신설은 11.7/12, 통과 2/3. P009가 3회 모두 "적용 범위 확인 필요"로 맞았고 정답에 없는 변경이 0이 됐다. DSR은 12.0/12로 돌아왔다.
고령자 기준은 7.7/12로 그대로 낮다. 실패 모양이 바뀌었다. 이제는 "신청 자격에 나이 상한이 없어 고령자와 계약할 수 있으니 고령자 정의 변경을 반영해야 한다"고 답한다 (P001 3회, 1 · 3회차에 P006 ~ P011). 13번 원칙의 "나이 상한 없음 = 계약 가능"이 정의 변경 요건으로 흘러든 것이라 프롬프트(14번)로는 막히지 않았다.
자료로는 확정된다. 규칙 82개 중 제15조(고령자 정의)를 따르는 규칙은 P002의 R010 하나뿐이다. 다음 단계(EXP-03)는 정의가 바뀐 요건에서 그 조항을 따르는 규칙이 없는 상품을 코드가 유지로 확정하는 것이다.

**EXP-03 분석.** 고령자 기준이 12/12, 3회 모두 통과. 설명 확인 신설은 11.3/12로 유지됐고 변경 대상 recall 9/9. 남은 흔들림은 P009(개인사업자)뿐이다. 적용 범위 밖이라며 유지(2회), 확정 불가라며 추가 확인(1회)으로 갈린다. 정답은 추가 확인이다.
DSR은 11.0/12로 내려왔지만 바뀐 코드와는 무관한 자리다. P005 2회는 모델이 다른 상품의 규칙 · 문서 ID를 인용해 코드가 "미조회 근거"로 보류시켰고, P002 1회는 적용 조건 인용문이 원문과 달라 보류됐다. 둘 다 Phase 1부터 있던 LLM 흔들림이다 (baseline의 P009 근거 누락, EXP-01의 P008과 같은 종류). 정의 정규식은 제8조 원문에 걸리지 않음을 확인했다. 같은 코드로 한 번 더 재서 흔들림 폭을 본다.

**EXP-03 재측정 · EXP-04 분석.** 재측정에서 고령자 P002(제15조를 따르는 R010=65)를 모델이 "65세가 60세보다 엄격하니 유지"라며 2회 보류했다. 한도의 원칙을 정의에 쓴 것이라, 정의를 옮겨 적은 규칙은 코드가 변경 대상으로 확정했다(EXP-04). 그 뒤 고령자는 다시 12/12 · 3회 통과다. 고령자 시나리오의 세 갈래(정의를 따르는 규칙 변경 · 따르는 규칙 없으면 유지 · 판매 종료 · 나이 상한 유지)가 모두 자료로 확정된다.
설명 확인은 2회 12/12였고 3회차에 P006 · P007 · P008이 "현재 절차가 새 의무를 충족하는지 단정 불가"로 되돌아가 9/12였다. 13번 원칙이 막으려던 바로 그 모양이라 프롬프트만으로는 매번 잡히지 않는다. 문서(OUTPUT_SPEC 2절)에 정한 대로 새 의무의 보류는 적용 범위가 불확실할 때만이므로, 적용 범위 조항을 근거로 들지 않은 보류는 코드가 변경 필요로 돌리는 것이 다음 단계(EXP-05)다.
DSR 2회차 8/12는 모델이 쓴 적용 조건 인용문이 원문과 달라 코드가 P001 · P002 · P005를 보류시킨 것이다(`condition_errors`). 이번 변경과 무관한 자리이고 Phase 1부터 있던 흔들림이다. 인용 검사를 느슨하게 하면 근거 검증이 약해지므로 그대로 두고 한계로 적는다.

개선 전후는 같은 평가셋 · 같은 모델 · 같은 실행 조건으로 잰다. 바꾼 것 하나에 한 줄. 되돌린 시도도 적는다.
